# 钉选之后，真的浮现一次

后端显示 pinned/anchor/core，不等于下一次开机的输出一定含它。还可能受到 token 预算、分类和排序影响。

1. 在真实后端完成钉选，保留返回结果。
2. 实际调用一次与开机相同的浮现入口。
3. 按准确 id 核对结果，不用“内容有点像”代替命中。
4. 没出现就报告未出现，检查预算/排序/是否属于不参与日常浮现的类型。
5. 精确检索仍可取回，不要因一次浮现没命中就宣称记录不存在。

`pin-check`做第二、三步，不负责钉选，也不改预算。`ombre-digest.sh`只提供本地待审计划，默认零写入。

消化时先取回完整原文，决定保留经历、短引用还是当前行动提示。解除钉选不等于删除记忆；不自动把高情绪内容归零，也不靠永远增加钉选解决遗忘。
